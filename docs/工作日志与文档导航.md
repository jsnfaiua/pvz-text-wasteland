- 侧面头顶"染发"：sprite-side 头顶有 9900+ 像素 `[126,82,43]`（**头发高光色**），距 shoes `[109,66,32]` d²=666，**比距 hair `[100,66,31]` d²=1076 更近** → 判给 shoes → 黑色头发染成棕块（"染发"）

**修复**：
1. MC_PAL.hair 加入 `[126,82,43]/[120,81,42]`（侧视 sprite 头发高光变体）→ 头发高光判给 hair → 染成玩家发色
2. nearestPart 加位置约束：`best === 'pants' && ny 0.28-0.55 → 'shirt'`（衣服区裤子色阴影改判 shirt）

**验证**：CDP 随机配色 east/west/south 截图 — 袖口干净、头顶无"染发"块、smoke-test 285 通过

### 8/9 增补 7 — 头发完整无"头皮"（移除 maskIsolatedPixels）

**用户报告**：
1. "现在头上的杂色已经修掉了" ✓
2. "头上那个头皮的感觉露出来了，就是头发走着走着，出来了，我想要完整的头发"
3. "就是肉色的像素点也不多"

**根因**：
`maskIsolatedPixels`（CC 连通分量 <4像素 mask 透明）原本用于去除 sprite 边缘"飞起来的脏块"，
但副作用严重——头发中的细发丝（1-3px 宽的独立连通块）也被 mask 成 alpha=0，
渲染时露出下面的肉色像素 → "头皮"。

**修复**：
- tintSprite 内**移除 maskIsolatedPixels 调用**
- 删掉整个 `maskIsolatedPixels` 函数（无引用）
- 头顶杂色已由 `nearestPart` 的"头发区域色相硬约束"（位置 + R>G>B 色相）
  彻底解决：顶部棕色像素被强制判给 hair → 染成玩家发色，不再需要 mask

**验证**：CDP 5 种发色（黑/金/绿/紫/红）截图 — 头顶完整无肉色像素点，smoke-test 285 通过

**教训**：mask 孤立块算法容易误伤正常细节。当杂色根因被定位（颜色匹配错误）
并用更精确的色相+位置约束解决后，原 mask 算法就可移除。

### 8/9 增补 8 — 头部杂色残余根除 + 素材不对称问题确认

**用户报告**：
1. "头发上有棕色，还有一点散落的色块，像棕色、肉色" → 头部残余杂色
2. "角色脖子上好像有杂色，手和衣服袖口叠起来的位置也有杂色" → 脖子/袖口杂色
3. "往南走裤腿右边下方有杂色，和左腿不太一样；头不对称，像缺了个耳朵" → 朝南走路帧素材问题

**根因**
1. 头部残余棕色：sprite 头顶深棕发丝 `[70,41,14]/[72,43,13]`（b=14/13）漏过旧色相约束
   （原 b>=15），被判给 shoes → 被 `ny<0.78→null` 挡住 → 保留原棕（"棕色散块"）
2. 头部绿色块：sprite-side/walk-side 头部有 `[42,78,38]` 等绿色阴影像素，距 MC_PAL.shirt
   d²=2185 较近 → 染成玩家绿衣色 → 头发位置出现绿色块
3. 裤腿/耳朵不对称：**用户提供的 walk-front-f2/f3 素材本身左右不对称**
   （右裤腿 `[15,27,39]` 深阴影 7755 像素、头部右侧多 4567 像素）——这是素材设计问题，
   tint 算法只能忠实染色不能修正形状

**修复**
1. 头发色相约束 b 下限 15→8：深棕发丝 `[70,41,14]` 也能判给 hair → 染成玩家发色
2. `best === 'shoes' && ny < 0.42 → 'hair'`：头部任何鞋色像素强制改判 hair
3. `best === 'shirt' && ny < 0.42 → 'hair'`：头部任何绿色像素强制改判 hair
   （躯干绿衣在 ny 0.35-0.65，头部不可能有绿衣）

**验证**：smoke-test 285 通过、full-run 0 异常

**遗留（素材层问题，算法无法修复）**：
- 朝南走路帧 walk-front-f2/f3 左右不对称（右裤腿阴影/头部轮廓差异）——
  这是用户提供的"往南走1/2.png"素材本身的问题，需重新提供左右对称的朝南走路帧
- 脖子/袖口交界处的杂色：系素材中该区域像素颜色分布自然过渡（肤色↔衣色），
  算法染色后交界处存在明暗过渡，属素材绘制效果

### 8/9 增补 9 — 发色影响上衣修复 + 捏脸界面四方向行走动画预览

**用户报告**：
1. "发色会影响上衣的上半颜色了" → 上衣上半被误染成发色
2. "脖子处好像有像素点，衣服的像素点" → 脖子/衣领交界杂色
3. "捏脸系统界面能够很清楚地看到角色的瑕疵，统就放四格动画男主的各种方向行走的动画，
   这样看到局内的效果也好一点，然后循环播放的那种" → 捏脸预览改四方向行走动画

**修复**
1. **发色影响上衣上半（根因）**：上一轮 `best === 'shirt' && ny < 0.42 → 'hair'` 规则过宽——
   上衣上半（ny 0.35-0.42）被误判为 hair → 发色污染上衣。
   修正为 `ny < 0.35`（只作用于真正头部，躯干上衣从 ny 0.35 开始不受影响）
2. **脖子衣领像素点**：系素材中脖子区（肤色↔衣领过渡）自然绘制，算法染色后交界明暗过渡，
   属素材效果；已通过 ① 的收紧间接缓解（不再把脖子区上衣改判发色）
3. **捏脸界面四方向行走动画预览（功能增强）**：
   - `wlook.js` 的 `_thumbSprites` 从"仅 front 单帧"扩展为 front/side/back 各 4 帧 walk 帧
   - `drawPreview` 改为 `requestAnimationFrame` 循环：朝南→朝东→朝北→朝西，
     每方向 4 帧（160ms/帧），循环播放（12 帧一个周期）
   - 朝东方向（dirIdx===1）做水平镜像，与局内 `dir==='right'` 镜像逻辑一致，
     保证预览与局内视觉一致
   - 帧缓存：walk-front 只引用 f2/f3 交替（与 render.js WALK_FRAME_FILES.front 一致）

**验证**：smoke-test 285 通过、full-run 0 异常、CDP 实测捏脸界面 6 帧截图
（朝南 f2→f3→朝东→朝北→朝西）确认动画循环播放、四方向行走姿态正确

### 8/9 增补 10 — 眼睛被发色污染修复（MC_PAL.eyes 加变体 + 头部规则收紧到 0.30）

**用户报告**：
1. "衣服的上半身稍微减弱了一点" → 上半（ny 0.35-0.42）仍有头发污染
2. "袖子横截着一半，都基本上有被头发影响" → 袖子上半被头发色污染
3. "往南走的时候，这个眼睛就是头发的颜色" → 眼睛被染成发色
4. "东往西也是挡住眼睛，眼睛感觉就是一下变成头发的颜色，一下是眼睛的颜色" →
   走路帧交替时眼睛闪烁

**根因**
- 头发色相约束 `ny<0.42` 过宽：覆盖到眼睛（0.28-0.38）和袖子上半（0.35-0.45）
- 眼睛周边深色阴影（如 [50,35,25]）距 hair[0]=[55,36,21] 仅 d²=41，被判给 hair
  → 染成玩家发色 → "眼睛变头发颜色"
- 发色像素诊断（2026-08-09）：真实头发集中在 0-30%，30-50% 的"发色像素"实际是
  眼睛/袖子上半被误判

**修复**
1. **MC_PAL.eyes 加变体 [50,35,25]/[45,30,22]**（眼窝/脸部深色阴影）→
   这些像素判给 eyes 保留深色，不再被判给 hair
2. **头部规则全部收紧到 ny<0.30**（从 0.42/0.35）：
   - 头发色相约束 ny<0.30：只作用于真正头发带（0-30%）
   - shoes→hair 收紧到 ny<0.30
   - shirt→hair 收紧到 ny<0.30
   效果：眼睛（0.28-0.38）、袖子上半（0.35-0.45）不再被头发色相约束误判
3. 眼睛保留：眼睛色 [28,24,20] 保持不变（最近 eyes 变体，保留深色原色）

**验证**：smoke-test 285 通过；CDP 金色发色（#e8b85a）朝南走 f2/f3 + 朝东走截图：
眼睛保持深色（不被金色覆盖），袖子保持肤色（不被金色污染）

## 10. 开发前审计与止损纪律（2026-08-07 定）

- **开发前审计**：改代码前先读目标函数及调用方/依赖，评估影响面，禁止盲改。
- **无损改动**：禁止破坏既有功能与行为（含旧档兼容、联机零差异）；
  确需变更既有行为须先征得用户同意并标注「行为变更」。
- **及时止损**：发现改动损伤既有功能立即停止，先回滚/修复再继续，禁止带伤开发。
- **每次做完必查**：按 §9 验证矩阵跑对应验证 + 手工复查受影响流程，确认无破坏才提交。
- 规则细则见 `AGENTS.md` §11.8（硬性）。
