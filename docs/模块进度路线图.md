## 一、框架文档待修正的矛盾点

开发前请先修订《总框架.docx》以下问题，避免模块标准打架：

| # | 矛盾 | 建议 |
|---|------|------|
| 1 | 一个文件含"完整版"+"纯净版"两套标准（BOSS 开发与否、图鉴动画与否互相冲突） | 拆分为两个文件或删除旧版，只留"纯净版·最终定稿" |
| 2 | 联机要求"帧同步+状态同步混合"+"运算不集中房主"+"房主离线移交"三者无法共存 | 改为描述现实方案：主机权威模拟 + 快照同步；房主移交作为后续增强 |
| 3 | "全部代码移除注释" | 改为"注释只写为什么，不写是什么" |
| 4 | 防具/磁力菇机制复杂，与"纯净无衍生机制"定位冲突 | 移至"后续拓展"章节，或承认其为核心新机制并单独立项 |
| 5 | "自由种植（无间距、立体布局）"与"严格对标原版一代手感"冲突 | 二选一，或明确自由摆放仅限特定模式 |
| 6 | 图鉴要求立绘/动态预览动画，但项目是文字版、无美术资源 | 改为"文字简介 + 属性面板"，动画需求挂起到有美术资源时 |
| 7 | "配合 Git 实现存档防丢" | Git 管源码；存档防丢用导出/导入 JSON 实现，两者分开写 |
| 8 | 五大玩法无优先级 | 按本文第三节里程碑执行 |

## 三、建议里程碑排序

> 原则：先补框架已承诺的核心机制，再开新玩法；工程化保险最先做。

### M0 工程化保底（半天，最先做）
- 初始化 Git 仓库，建立 main/dev 分支，接 Gitee/GitHub 私有远程
- 补 .gitignore，首次打 Tag `v0.2.0`（当前可玩版本快照）

### M1 框架核心机制补全：防具系统（框架最大缺口）
- zombieConfig 补铁质/非金属材质标签
- 击杀防具掉落（20% 护甲、持续损耗）+ 防具背包
- 防具装备给玩家/植物（单株限一件、优先承伤）
- 磁力菇植物（吸附铁质防具、满护甲、优先级高于掉落）
- adventureUI 防具快捷背包栏

### M2 联机深化
- 大厅：密码房、准备状态、人数上限、房主权限管控
- 战斗：植物种植者昵称标注、击杀公告、侧边玩家列表（昵称/阳光/存活）
- 健壮性：断线重连、房主离线移交
- 同步修订框架联机章节为"主机权威+快照同步"现实方案

### M3 图鉴与转盘收尾
- 图鉴问号蒙版未解锁机制（接 systems/almanac.js 已有钩子）
- 扇形概率转盘 UI + 概率公示面板（替换现有 gacha 或并存）
- 卡槽上限开放至 10 格
- 修复"初始阳光/波次休整"滑块单机无效问题

### M4 存档增强
- 存档导出/导入 JSON（替代框架中"Git 管存档"的错误表述）
- 对局临时快照与永久存档分离

### M5+ 拓展玩法（每个单独评估工作量，均大于现有项目体量）
- 肉鸽试炼 → 生存大世界 → 炉石卡牌（建议按此顺序，肉鸽复用现有战斗最多）
- 多玩法中心大厅入口随首个拓展玩法一同上线
- 僵王 BOSS 维持搁置，待拓展玩法落地后再评估
