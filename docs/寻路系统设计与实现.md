# 8 方向 A* 寻路系统 · 设计与实现

> 评审/实现：高级开发工程师
> 对象：荒原模组（mod-wasteland）寻路体系
> 状态：**阶段一（僵尸流场）+ 阶段二（NPC 寻路）均已落地 ✅，回归全绿**
> 结论：**8 方向 A* 在当前代码库中已有三个实现（僵尸/车辆/NPC），"引入 A*"实质是"给现有 Dijkstra/BFS 补启发式"；按本文方案实施不会破坏现有寻路逻辑。**

## 一、地图数据以什么方式存储

### 1.1 三层结构（world.js）

| 层 | 存储 | 说明 |
|---|---|---|
| 种子世界 | `sv.world = { seed, chunks: Map }` | 同一 seed + 区块坐标永远生成同样内容；地形不进存档，存档只存 seed + 玩家差分 |
| 区块 | `chunks: Map<"cx,cy", { tiles }>`，CHUNK=16 | `genChunkTiles(seed, cx, cy)` 纯函数生成 `tiles[y*16+x]` 一维数组；按需生成、远离玩家 >8 区块卸载（`purgeChunks`） |
| tile 编码 | 单字符常量 `T`（world.js 顶部） | `.` 地面、`路` 公路、`墙` 墙、`木` 树、`水` 积水、`车` 汽车……共 27 种 |

### 1.2 修改与保护

- **玩家改动存差分**：`sv.mods.tiles["gx,gy"] = { t, built? }`；`setTile` 会递增 `sv._zombiePathRevision` 触发寻路场失效。
- **城市规划保护层（纯函数）**：`gridRoadKept` / `plannedSidewalkAt` / `plannedArterialAt` 在 `getTile` 时恢复道路/人行道，防止玩家挖断公路。
- **读地图一律走 `getTile(sv, gx, gy)`**，它是唯一权威出口（原生 tile → 差分 → 规划保护层）。

### 1.3 可通行判定链（寻路必须复用的唯一入口）

```
isWalk(t)         基础判定：GROUND/FLOOR/HERB/FLOWER/CROP/WEED/ROAD/SIDEWALK 可走
walkableAt(gx,gy) isWalk + 车体占位（carBodyAtFast，帧级缓存）+ 自造门（built DOOR 可穿）
zCanStand(x,y)    四角采样（±11px），僵尸/玩家共用；自造门不可穿
carCanStand(x,y,dir) 车体矩形（长2格×宽1格，按朝向旋转）；废墟碎石可压、墙/树/水/路障不可过
```

## 二、现有寻路盘点（关键事实）

| 寻路者 | 算法 | 方向 | 数据结构 | 关键约束 |
|---|---|---|---|---|
| **僵尸** wzombie.js | 反向 A*/Dijkstra（**h=0**，注释明确"启发式为 0，等价 Dijkstra"） | 8 向 | 二叉堆 + 共享 `parent` 表 + `reachable` 集 | 单次搜索服务全部僵尸；`PATH_MAX_NODES=12000`；斜穿禁过两障碍角；`revision` 键控重建（0.5s 冷却） |
| **车辆** wvehicle.js | 0-1 BFS（公路优先双队列） | 8 向 | `seen` Map + waypoint 路径 + 共线压缩 | 包围盒剪枝（margin 单调增）；四层局部缓存（tile/朝向/第二格/体格）；转弯 3×3 净空；车体长轴沿移动方向 |
| **NPC/玩家** wnpc.js | 目标格小 BFS | 8 向 | `pathStepTo` 每实体独立搜索，0.4s 缓存 | 上限 3000 节点；近距直线兜底 + 随机偏转试探 |

**核心结论：代码库已经"广度遍历八个方向 + A* 骨架"了，缺的只是启发式函数（h）。**
- 僵尸流场：h=0 → 加 octile 启发式后变成真正的 A*，**路径结果不变**（一致启发式保证最优），只是扩展节点变少、更快。
- NPC pathStepTo：纯 BFS → 可替换为带启发式的 A*。
- 车辆：0-1 BFS 是刻意为"公路优先 + 车体约束"设计的，**不应替换**。

## 三、A* 设计（新增模块）

### 3.1 模块位置与接口

新建 `source-code/mod-wasteland/wpath.js`（保持模组内聚，依赖方向同现有模块）：

```js
// 单点寻路：返回格路径 [{x,y}, ...]（不含起点，含终点）
export function astarPath(sv, sx, sy, gx, gy, opts);
// 反向流场：以目标为根展开，返回 parent 表（僵尸多实体共享场景用）
export function astarField(sv, tx, ty, canStand, opts);
// 最近可达兜底：目标不可达时返回 BFS/A* 扩展中离目标最近的格
export function nearestReachable(sv, sx, sy, gx, gy, canStand, opts);
```

`opts`：`{ canStand, maxNodes, heuristic, weightRoad, weightDiag }`。

### 3.2 代价与启发式

- 移动代价：正交 10、对角 14（与现有 `PATH_DIRS` / `cost+14` 完全一致，保证路径可比）。
- 启发式：**octile**（`10*(dx+dy) + 4*min(dx,dy)`）——与 8 方向移动代价一致、可采纳，保证最优且比欧氏更快。
- 可选公路加权：`ROAD/SIDEWALK` 格代价 ×0.7 → 更"拟人"（贴路走），但**会改变路径形状**，默认关闭，由调用方显式开启。
- 平局处理（tie-break）：`f = g + h`，再按"后进者优先/固定方向序"打散，**必须确定化**（Map 遍历序、堆内比较都要稳定），否则同 seed 行为漂移，破坏联机与回归测试。

### 3.3 硬约束（从现有实现继承，缺失会出 bug）

1. **斜穿检查**：`dx && dy` 时必须检查两个正交邻格可走，否则斜穿墙角。
2. **节点上限 + 包围盒剪枝**：`maxNodes`（僵尸 12000 / NPC 3000 保底）+ 起点↔终点矩形外扩 margin（借鉴车辆 MARGIN）。
3. **不可达兜底**：目标被墙/水/车围死时返回"最近可达格"（车辆 best 逻辑），禁止返回空路径让调用方悬空。
4. **可通行判定注入**：A* 内部绝不直接调 `getTile`，只调注入的 `canStand`，这样僵尸版（zCanStand）、NPC 版（canStand）、车版（carCellOk）各取所需。

### 3.4 缓存与失效

- 单点寻路结果缓存：`key = sx,sy>gx,gy` + `sv._zombiePathRevision` 版本号，版本变化即失效（复用现有 `_zombiePathRevision` 机制，`setTile` 已自动递增）。
- 僵尸流场继续挂在 `sv._zombiePathField`，保留 `_pathRebuildCd` 冷却防每帧重建。

## 四、会不会破坏当前寻路逻辑？（风险逐条评估）

### 4.1 零风险路径（推荐首阶段）

**新增模块，不替换任何现有入口。** 僵尸/车辆/NPC 的调用代码一行不动，A* 只作为新能力供给（任务导航点、BOSS 追踪、车队调度）。→ 无破坏面。

### 4.2 若替换僵尸流场（收益最大，风险可控）

| # | 风险点 | 说明 | 对策 |
|---|---|---|---|
| 1 | **流场语义** | 现有是"反向多目标搜索"，一次服务所有僵尸；改成正向逐僵尸搜索 → N 倍开销 | 保留"反向流场 + 共享 parent"形态，只把 h=0 换成 octile。**一行改动** |
| 2 | **路径结果一致性** | 一致启发式（octile）保证 A* 与 Dijkstra 最优路径相同 → 僵尸行为不变 | 默认不加公路加权；加权必须过回归测试 |
| 3 | **失效机制** | 地形变化靠 `_zombiePathRevision` + `_pathRebuildCd` 失效 | 新代码必须接入同一版本号，禁止自建失效逻辑 |
| 4 | **节点上限** | `PATH_MAX_NODES=12000` 同时是"不可达判定"的隐性边界 | 保留上限；A* 剪枝后通常远到不了上限，行为只会更稳 |
| 5 | **斜穿墙角** | 现有 `!zCanStand(...) || !zCanStand(...)` 检查 | 必须原样保留 |
| 6 | **确定性** | 现有搜索顺序确定 → 同 seed 可复现（有回归测试依赖） | 堆比较 + tie-break 确定化；先跑 `car-pathfinding-test.js` 再合入 |

### 4.3 禁止替换的场景

- **车辆 BFS**：车体长轴方向、转弯 3×3 净空、公路优先双队列、共线压缩都是车辆专属约束，通用 A* 装不下，**保持现状**。
- **NPC 近距逻辑**：`dist ≤ TS*1.2` 直线兜底 + 被挡随机偏转是防罚站保险，替换时必须保留。

### 4.4 回归测试门禁

1. `node dev-tools/car-pathfinding-test.js` 全绿（车辆不动，作为环境基线）。
2. 新增 `dev-tools/pathfinding-test.js`：随机 seed × 随机起终点，断言 A* 路径代价 ≤ Dijkstra 代价、路径不穿墙、不可达时返回最近可达格。
3. 同 seed 两次运行路径逐格一致（确定性断言）。

- **阶段一（低风险，建议立即做）**：新建 `wpath.js` 提供 `astarPath` / `astarField`；僵尸流场 `buildPlayerPathField` 内部把堆键从 `cost` 换成 `cost + octile(start→cur)`（一行 + 一个函数），跑回归测试。预期扩展节点数下降 30–60%，卡顿缓解。

## 六、一句话总结

地图是 **seed 驱动的无限 chunk 世界 + 差分修改 + 规划保护层**，可通行判定链是寻路的唯一数据出口；现有三套寻路都已是 8 方向，**A* 的正确打开方式是"给僵尸流场补 octile 启发式"而不是重写**——按此设计实施，不破坏任何现有寻路逻辑，车辆与 NPC 的专项约束继续保留。

## 七、实施记录（阶段一已落地 ✅ 2026-08-05）

### 7.1 新增模块 `source-code/mod-wasteland/wpath.js`

- `astarField(sx, sy, targets, opts)`：多目标反向 A* 流场，返回 `{ parent, reachable }`（与旧僵尸流场同构）。标准 A*：**gScore 更新 + 懒删除**（修正了旧"首次发现即锁定"的次优隐患，路径保证最优）。
- `astarPath(sx, sy, tx, ty, opts)`：单点寻路（反向流场反查），返回格路径，新功能直接用。
- `octile` 启发式：8 方向代价（正交10/对角14）的一致下界，可采纳 → 路径与 Dijkstra 最优一致。
- 启发式三档：`'min'`（到最近目标，目标 ≤64 时默认）/ `'box'`（包围盒下界，目标多时省 O(targets)）/ `'none'`（纯 Dijkstra）。
- 硬约束继承：8 方向、斜穿禁过两障碍角、`maxNodes` 上限、只依赖注入的 `canStand`（不读 tile）。

### 7.2 僵尸流场切换 `wzombie.js`

- `buildPlayerPathField` 改为调用 `astarField`（`PATH_MAX_NODES=12000` 语义保留）；`getPlayerPathField` 的 revision 缓存机制、`playerKey`/`revision` 字段、斜穿检查全部不变。
- 删除原模块私有的 `PATH_DIRS`（不再使用）。

### 7.3 对照验证 `dev-tools/astar-verify.mjs`（硬断言）

| 场景 | 目标样本 | 断言失败 | 耗时对比 |
|---|---|---|---|
| 6 种子 × 3 轮（含孤岛不可达） | 300 | **0** | 快 58% |
| 24 种子 × 2 轮 | 1200 | **0** | 快 38.5% |
| 10 种子 × 4 轮 | 1000 | **0** | 快 14% |

断言内容：① 不丢可达性（旧可达 → 新必可达）② 路径代价不劣于旧 Dijkstra（不绕远）③ 不穿墙/不跳格 ④ `astarPath` 单点路径连续、终点正确、代价与流场一致。

### 7.4 回归测试全绿

- `smoke-test.js`：138 通过 0 失败 ✅
- `full-run-test.mjs`：3 种子全流程（含僵尸寻路场）0 异常 ✅
- `car-pathfinding-test.js --trials 20`：137 通过 0 失败 ✅（车辆寻路零改动，环境基线确认未受影响）

### 7.5 验证经验（团队可复用）

- **10/14 权重的"等代价平局"**：5 步对角（70）与 7 步直行（70）代价相同但**步数不同**——断言"步数"会误报绕远，必须断言**代价**（10×直行 + 14×对角）。
- 回溯代价统计**第一步也要计入**（从目标格坐标起算，勿跳过首边）。
- 多分散目标场景 A* 剪枝收益有限（需覆盖全区域），但耗时仍快（懒删除减少堆操作）；**目标集中场景（僵尸聚拢追玩家）收益最大**。
