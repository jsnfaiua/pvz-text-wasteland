## 一、目标拆解（7 个子系统）

1. **区域与资源富集**（S1）—— 资源不再均匀散落，按区域聚集
2. **建筑分型**（S2）—— 学校/医院/民宅/商店/仓库，各有资源画像
3. **城区要素**（S3）—— 公路、汽车、路障
4. **楼层/地下城系统**（S4）—— 进建筑可上下楼，逐层深入
5. **图鉴特殊僵尸**（S5）—— 撑杆/旗帜/铁门，行为对齐本体
6. **功能性交互物件**（S6）—— 房间物件有交互且有实际作用
7. **野外作物**（S7）—— 萝卜/玉米/土豆等可采集食物

依赖关系：**S1 是地基**（区域决定建筑分布与资源密度）→ S2/S3 依赖 S1 → S4 依赖 S2 → S5 独立可并行 → S6 依赖 S4 → S7 依赖 S1。

## 二、S1 区域与资源富集

### 现状问题
资源（箱/草/木）按每格固定概率散落，全图密度一致，没有"富集区"概念，探索缺乏目标感。

### 设计
把"群系(biome)"升级为"区域(district)"，区域是更大尺度的连续片区，各区有**资源密度、僵尸密度、建筑类型、危险度**画像。

**区域类型（4 类，替代现 3 群系，向后兼容映射）：**

| 区域 | 代号 | 资源密度 | 僵尸密度 | 建筑 | 特征 |
|---|---|---|---|---|---|
| 城区核心 | `urban` | 高 | 高 | 学校/医院/商店/仓库/民宅，密集 | 公路网、汽车、路障、特殊僵尸多 |
| 郊区 | `suburb` | 中 | 中低 | 民宅散布 | 过渡带，少量车 |
| 荒野 | `wild` | 低（建材少） | 低 | 无 | **野外作物富集**（萝卜/玉米/土豆）、树、水、中立植物 |
| 废墟 | `ruins` | 中（弹药/零件多） | 高 | 残破建筑 | 碎石、危险、好装备 |

**区域生成策略（关键决策点 ①）：**
- 用**低频噪声**做区域场：以 `floor(区块/REGION_SIZE)` 为单元（REGION_SIZE≈4，即 64×64 格一大区），同一单元同区域，形成**连片大区**而非碎块。
- 资源密度 = 区域基础密度 × 局部噪声。建筑只在 urban/suburb/ruins 生成，荒野不生成建筑（改为作物）。
- 出生区 (0,0) 固定 suburb（安全起步），向外随距离/噪声过渡到 urban/wild/ruins。

**配置化（wbalance.js 新增 `DISTRICTS` 表）：**
```js
export const DISTRICTS = {
    urban:  { name:'城区', resMul:1.6, zombieMul:1.5, buildDensity:0.9, danger:3 },
    suburb: { name:'郊区', resMul:1.0, zombieMul:0.7, buildDensity:0.4, danger:1 },
    wild:   { name:'荒野', resMul:0.5, zombieMul:0.5, buildDensity:0.0, danger:1, crops:true },
    ruins:  { name:'废墟', resMul:1.2, zombieMul:1.4, buildDensity:0.5, danger:3 },
};
```

**存档兼容：** 地形仍由 seed 确定性生成、不进存档。区域算法改了 → 旧存档的世界内容会变，但存档结构（seed+差分）不变，**结构向后兼容，内容重生成**（可接受，会在文档标注；老玩家进旧档等于换了个世界布局，差分修改仍保留）。

## 三、S2 建筑分型

### 设计
每栋建筑有**类型**，决定外观标签、楼层数、资源画像、僵尸配置。建筑类型由建筑位置 hash 确定性决定（同位置永远同类型）。

**建筑类型表（wbalance.js 新增 `BUILDING_TYPES`）：**

| 类型 | 标签 | 楼层 | 资源画像 | 僵尸倾向 |
|---|---|---|---|---|
| 民宅 | 宅 | 1~2 | 食物/木材/生活杂物 | 少 |
| 学校 | 学 | 2~3 | 食物/纸张/工具，量大 | 中 |
| 医院 | 医 | 2~3 | 草药/医疗包/食物 | 中（感染多） |
| 商店 | 店 | 1 | 弹药/武器/零件 | 中 |
| 仓库 | 仓 | 1~2 | 木材/石材/零件，量大 | 多 |

建筑标签显示在大世界（如"学"字），玩家可预判资源。建筑门进入后走 S4 楼层系统。

## 四、S3 城区要素

| 要素 | 字符 | 通行 | 交互 | 说明 |
|---|---|---|---|---|
| 公路 | `路` | 可走 | 无 | 连接建筑的硬化路面，移动略快（可选） |

## 五、S4 楼层/地下城系统（最大结构改动）

### 现状
`windoor.js` 进门→单个 12×10 房间。无楼层概念。

### 设计
把"单房间"泛化为"多楼层建筑"。进门 = 进入该建筑**第 1 层**，楼内有**楼梯(上/下)**，逐层深入，越深越危险、资源越好。地下城式但保留本模组搜刮+建造+尸潮玩法。

**数据结构（扩展 `sv.interior`，决策点 ② 差分存档方案）：**
```js
// 玩家在楼内时的会话状态（进楼生成、离楼清空，持久部分下沉到 sv.mods.interiors）
sv.interior = {
    buildingKey,          // 建筑唯一键（由门坐标推）
    type,                 // 建筑类型（民宅/学校…）
    floors: N,            // 总层数（地上 FLOOR_MAX_ABOVE + 地下 FLOOR_MAX_BELOW，仅 school/hospital/warehouse 有地下）
    cur: 1,               // 当前层（地上从1起，地下从-1起）
    tiles, w, h,          // 当前层地图（楼梯格 IT.STAIR_UP / IT.STAIR_DOWN）
    exitX,                // 回到大世界的出口（仅第1层有）
    zombies,              // 当前层僵尸列表（含已扣血量，离楼时写回差分）
    drops,                // 当前层掉落物
    searchedBoxes,        // 当前层已搜箱子坐标列表（离楼时写回差分）
};

// 每栋建筑的持久差分（进存档，向后兼容旧值 1）
sv.mods.interiors[buildingKey] = {
    cleared: false,                  // 整栋是否清剿
    clearedFloors: [],               // 已清剿层号列表
    floorDiffs: {                    // 每层被玩家改动的差分（未访问的层无键）
        [cur]: {
            searchedBoxes: [[x,y], ...],   // 已搜箱子
            zombieHp: { [zid]: hp },       // 打过但未死的僵尸残余血量
        }
    },
};
```

**楼梯行为：** 踩到 `STAIR_UP` -> `cur++` 重新生成上一层；`STAIR_DOWN` -> `cur--`。第 1 层有 EXIT 回大世界。每层地图由 `(seed, buildingKey, cur)` 确定性生成，**同层永远同布局**；玩家改动（已搜箱子/打过的僵尸血量）从 `floorDiffs[cur]` 叠加还原。

**逐层难度/奖励曲线（`wbalance.js` `FLOOR_SCALE`，决策点 ④ 已定）：** 层数越高，僵尸数量 `FLOOR_ZOMBIE_MUL`、血量 `FLOOR_HP_MUL` 按层系数提升，掉落品质 `FLOOR_DROP_BUMP` 在地下层+1档。地下室（cur<0，学校/医院/仓库可有）奖励最好。

**清剿记录：** 现 `sv.mods.interiors{doorKey:1}` 升级为 `{doorKey:{cleared, clearedFloors, floorDiffs}}`（向后兼容：旧值 `1` 视为整栋已清、无楼层差分）。

**存档兼容要点（关键决策点 ② 已定：差分存档）：** 室内从"重生成+清剿标记"升级为"差分存已搜格子+僵尸残余血量"。层布局靠 `seed+层号` 重生成，存档只存玩家改动，体积小；离楼再回，未清剿层的僵尸血量保留（从 `floorDiffs[cur].zombieHp` 还原）。

## 六、S5 图鉴特殊僵尸（对齐本体）

### 现状
`wzombie.js` 只用 normal/cone/bucket，行为全是"追击/游荡/啃"，无特殊能力。本体图鉴有 flag/pole/door。

### 设计
接入剩余图鉴僵尸，行为**对齐本体图鉴描述**，适配到顶视角生存：

| 僵尸 | 本体描述 | 荒原行为（顶视角适配） | 数据源 |
|---|---|---|---|
| 撑杆 pole | 极快，跳过遇到的第一棵植物 | 速度极快(speed 34)；遇到**第一个障碍(路障/墙/玩家建的墙)** 撑杆跳过一次，之后正常 | `ZOMBIES.pole` jumper:true |
| 旗帜 flag | 领头，指引尸群 | 尸潮/尸群领头；**周围僵尸加速光环**，优先击杀可瓦解加速 | `ZOMBIES.flag` |
| 铁门 door | 铁门护盾，正面防御极强 | 持盾面朝玩家，**正面减伤至 0.4 倍**（仅站定蓄力举盾时生效），需绕侧/破盾 | `ZOMBIES.door` armorHp:1100；**荒原实际 HP=500**（非本体 1100，避免打不动） |

数值直接引用 `constants.ZOMBIES`（pole speed:34 / door armorHp:1100），荒原只做行为层，数值对齐本体。

**配置化（wbalance.js 新增 `ZOMBIE_BEHAVIOR`）：** 各特殊行为的触发/数值（撑杆跳跃次数、旗帜光环范围/加速、铁门减伤比例）。

**生成策略：** 撑杆/铁门随天数解锁（类似现 cone/bucket 的天数门槛）；旗帜随尸潮/尸群领头出现。城区/废墟出现率更高（关联 S1 区域 danger）。

## 七、S6 功能性交互物件

### 现状
室内只有 BOX(搜刮)/SHELF/DEBRIS，箱子是纯搜刮，无"有作用的交互物件"。

### 设计
新增一批**有实际作用**的可交互物件（F 交互），不只是搜刮：

| 物件 | 字符 | 交互作用 | 一次性 |
|---|---|---|---|
| 医疗包 | `医` | F 直接回血 | 是 |
| 工作台 | `台` | F 修理武器/制作（联动武器耐久，后续） | 否（可用多次） |
| 保险箱 | `险` | 上锁，需钥匙，开 better loot | 是 |
| 发电机 | `电` | 给建筑供电→开灯（降该层危险/视野） | 否 |
| 收音机 | `音` | 揭示地图/给增益/剧情 | 是 |
| 净水机 | `净` | 产净水（联动生存，后续） | 否 |

初期先做 医疗包(回血) + 保险箱(钥匙+好装备) + 工作台(修理)，其余挂后续。物件配置进 `wbalance.js`。

## 八、S7 野外作物

### 设计
荒野区域（S1 wild，crops:true）生成可采集作物，替代部分散落资源，提供食物来源并衔接现有培养系统。

| 作物 | 字符 | 采集 | 产出 |
|---|---|---|---|
| 萝卜 | `萝` | F | 食物 |
| 玉米 | `米` | F | 食物 |
| 土豆 | `豆` | F | 食物 |
| 野菜 | 复用草 | F | 食物/草药 |

作物可掉**种子**，衔接 M6 培养系统（种子+水+肥+阳光→防御植物）。作物为可再生资源点：**采集后消失，该地块按 seed 在 `CROP_REGEN_DAYS`（=3）天后再生**（决策点 ③ 已定）；存档记 `sv.mods.crops{tileKey: 采集时天数}`，地形仍由 seed 重生成，再生判定为 `当前天数 - 采集天数 >= 3`。
