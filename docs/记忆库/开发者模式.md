## 一、领域概述

开发者模式（AGENTS.md §13.14 硬性）：**所有新开发功能必须提供开发者模式测试入口**（`wdev.js` 局内 F9 面板 + `saveData.devMode`），保证功能无需走完整自然流程即可直接验证（直接召唤/设状态/触发结算）。**对任何玩家开放**（单机 / 联机 host / 联机 guest，无权限门槛）。

---

## 二、核心技术

| 技术 | 说明 |
|---|---|
| **F9 面板** | `wdev.js` 局内开发者面板：属性/物品/召唤/状态/时间/倍率等测试入口 |
| **devMode 开关** | `saveData.devMode` 持久化开发者标志；默认关闭，仅主动开启时生效，不影响正常玩家体验与数值平衡 |
| **联机 dev 上报** | 属性类走 `devflags` 上报（host 权威 → wsync 回传双端共用）；召唤/结算类走 `devcmd`（host 权威执行 → 双端可见）——遵循 §6 host 权威模型，**不得因「是 guest」而禁用 dev** |
| **环内模块** | wdev 位于循环依赖区（`wvehicle → wdev → wnpc → wvehicle`），勿新增环边 |

## 五、验证方式

| 场景 | 命令/做法 |
|---|---|
| 新功能完成后 | dev 面板必须能测到该功能（或 wdev.js 注释说明用哪个现有入口测），纳入 §9 验证矩阵（AGENTS.md §13.14） |
| 改 dev 功能 | 启动游戏 → 开启 devMode → 用面板直接验证（无需走自然流程） |
| 联机 dev | 双端 CDP 实测：guest 开启 dev 也能用（devflags/devcmd host 权威回传） |

## 六、历史教训

1. **dev 不因 guest 禁用**：联机下属性类 `devflags` 上报回传、召唤类 `devcmd` host 权威执行，双端可见；不得因「是 guest」而禁用 dev（AGENTS.md §13.14）。
2. **默认关闭**：dev 入口默认关闭，仅主动开启时生效；不得影响正常玩家体验与数值平衡（§13.1 / §13.7）。
3. **新功能必须可测**：任何新功能完成后 dev 面板必须能测到，否则未达 §13.14 硬性要求。
4. **环内模块**：wdev 位于循环依赖区，新增功能不得把新模块拖入环内（AGENTS.md §1）。
