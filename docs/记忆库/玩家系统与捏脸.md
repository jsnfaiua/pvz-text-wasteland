# 玩家系统与捏脸 · Agent 记忆

> 所属记忆库：`docs/记忆库/`｜主索引：[`../../AGENTS.md §14`](../../AGENTS.md)
> 相关模块：`mod-wasteland/waction.js`、`wlook.js`、`render.js`（角色渲染部分）

---

## 一、领域概述

玩家系统负责移动/动作（闪避/冲刺）与苏醒流程；捏脸系统负责角色外观定义（发型/表情/配色）与预览。角色像素染色（`tintSprite` / `nearestPart`）是 8/9 多轮杂色修复的核心战场，与 [渲染系统](渲染系统.md) 紧密相关。

---

## 二、核心技术

| 技术 | 说明 |
|---|---|
| **动作系统** | `waction.js moveInput`：玩家移动输入（苏醒期间返回 0 锁移动）、闪避/冲刺 |
| **捏脸系统** | `wlook.js`：发型三款/表情/配色，`randomLook()` 随机配色为起点 |
| **角色像素染色** | `render.js tintSprite` + `nearestPart` + MC_PAL 部位色板（肤色/瞳色/鞋色窄域）+ 色相/位置约束 |
| **朝向镜像** | `dir === 'left'` 才水平镜像（朝东原图 + 朝西镜像），与素材方向一致 |
| **四方向行走动画预览** | 捏脸界面 requestAnimationFrame 循环：朝南→朝东→朝北→朝西，每方向 4 帧（160ms/帧），12 帧一个周期 |
| **苏醒流程** | `startRun` 内 `playT<=0 && day<=1` 设 `sv._wake`；`moveInput` 苏醒期锁移动；`drawWakeOverlay` 睁眼渐变 + 苏醒无敌 |

## 三、关键代码改动

| 位置 | 改动内容 |
|---|---|
| `waction.js:moveInput` | 玩家移动输入（苏醒期间返回 0 锁移动） |
| `wlook.js:randomLook()` | HSV 全色域随机配色（肤色/瞳色/鞋色窄域），扩充固定色板；新建角色以随机配色为起点 |
| `wlook.js:_thumbSprites` | 捏脸预览从「仅 front 单帧」扩展为 front/side/back 各 4 帧 walk 帧 |
| `wlook.js:drawPreview` | requestAnimationFrame 四方向行走动画循环 + 朝东水平镜像 |
| `render.js:tintSprite` | 逐像素部位染色（MC_PAL 匹配 + 色相/位置约束） |
| `render.js:nearestPart` | 部位分类 + 位置/色相软硬约束（shoes 位置约束、底部 hair→shoes、头部改判 hair） |
| `render.js:nearestPalRef` | 亮度缩放基准（保留原图明暗层次） |
| `render.js` 镜像条件 | `dir === 'right'` → `dir === 'left'`（修复朝东视角反向） |
| `survival.js` `startRun` / `drawWakeOverlay` | 苏醒流程：睁眼渐变（单调变亮 + blur + 灰雾）+ 苏醒无敌/状态冻结 |
| sprite 替换 | 用用户素材覆盖 walk-side/front/back、sprite-front/back/side（治本消除撞色） |

## 六、历史教训（8/9 角色染色大修的沉淀）

1. **MC_PAL 必须匹配实际素材**：核心问题不是 tint 算法，而是 MC_PAL 颜色与素材不匹配；更新 MC_PAL 后基础判定就准了，再精确位置约束根除杂色。
2. **对照原图判断语义**：tint 后颜色与原图对应位置语义一致（眉毛是头发→染成发色正确）则不是 bug，停止过度修改（否则陷入「修了 A 坏 B」循环）。
3. **镜像方向**：用户素材是「朝东视角」原图，朝西才镜像；`dir === 'left'` 才镜像。注释与代码不一致曾导致朝东视角反向。
4. **mask 孤立块算法易误伤细节**：`maskIsolatedPixels` 会 mask 掉细发丝 → 头皮；当杂色根因用色相+位置约束解决后可移除 mask。
5. **苏醒无敌**：苏醒期间状态冻结 + 免伤，避免「开局被怪打死」；`moveInput` 苏醒期锁移动（AGENTS.md §6 教训 8 关联暂停同步）。
