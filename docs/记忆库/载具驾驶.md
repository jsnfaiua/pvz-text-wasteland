# 载具驾驶 · Agent 记忆

> 所属记忆库：`docs/记忆库/`｜主索引：[`../../AGENTS.md §14`](../../AGENTS.md)
> 相关模块：`mod-wasteland/wvehicle.js`

---

## 一、领域概述

载具系统支持修理/拆解/驾驶（玩家 + NPC 分帧 BFS 寻路）。驾驶分**手动驾驶**与**自动驾驶**（代驾/送目标区域）两种。核心难点是汽车 BFS 寻路与性能平衡（驾驶 BFS 分帧 P0-4）。

---

## 二、核心技术

| 技术 | 说明 |
|---|---|
| **汽车 BFS 寻路（公路优先 0-1 BFS）** | `CAR_PATH_DIRS` 只走十字方向（车体 2 格宽不斜插），一次算完整格子路径，沿 waypoint 逐格走，被挡才重建 |
| **分帧寻路（P0-4）** | `chauffeurBfsStep` 按每帧扩展格数跨帧推进（`CHAUFFEUR_BFS_FIRST_CELLS=6000` / `REBUILD_CELLS` 时间预算），**确定性**（与 CPU 无关）；重建期间保留旧路径不中断行车 |
| **车体 2×2** | BFS 车体与实际 `canStandCar` 4 角一致（此前 2×3 过严） |
| **自动驾驶兜底三件套** | `autoRepark`（泊车）、`forceEject`（卡死强制弹车）、蠕动式卡死保护（`_absMin` 30s 无 2 格实质改善即优雅停车） |
| **乘客落点 null 安全** | 下车环以已验证可站车门为中心环绕散开，`canStand` 为 null 时退化为逐格 isWalk 判定 |

## 三、关键代码改动

| 位置 | 改动内容 |
|---|---|
| `wvehicle.js:CAR_CORNERS` | **BFS 车体 2×3→2×2**：此前 2×3 格（6 角点）比实际驾驶严格，废墟残路（4 格宽）里车体格贴边判不可走 → 手动能开的路导航判不可达（「送废墟」根因） |
| `wvehicle.js:chauffeurBfsInit` / `chauffeurBfsStep` / `chauffeurBacktrack` / `chauffeurBuildPath` | 分帧 BFS 状态机 + 局部缓存四层（tile/车体朝向/第二格/体格检查）+ 起点↔终点包围盒剪枝 |
| `wvehicle.js:autoRepark` | 自动泊车（自动驾驶兜底一） |
| `wvehicle.js:forceEject` | 卡死强制弹车（自动驾驶兜底二） |
| `wvehicle.js:updateChauffeurDrive` | 自动驾驶帧循环 + 蠕动保护 + 路点消耗 + 优雅停车 |
| `wvehicle.js:driveCommon` | **NPC 坐车冻结修复**：每帧把 riding NPC 坐标钉在车中心（僵尸咬扫/追击距离判定基于 n.x/n.y） |
| `wvehicle.js:stopDrive` | **乘客落点 null 安全**：`canStand` null（finishDriveOrder 调 stopDrive(sv,null)）时退化为逐格 isWalk 判定 |
| `wvehicle.js:startDrive` / `crash` / `carBodyDirCached` | 启停驾驶 / 碾压 / 碰撞 / 车体朝向 |

## 六、历史教训

1. **车体 2×3→2×2**：BFS 体格过严导致「手动能开、导航判不可达」，必须与实际 `canStandCar` 4 角一致（8/6 修复）。
2. **分帧必须确定性**：驾驶 BFS 分帧与 CPU 无关，改它可能破坏单机/联机一致性（P0-4）。
3. **NPC 坐车冻结**：车开走后僵尸咬「幽灵成员」，必须每帧把 riding NPC 坐标钉在车中心。
4. **空 canStand 崩溃**：乘客下车 `canStand` 为 null 时必须退化逐格 isWalk，否则崩溃（P0-4 null 安全）。
5. **兜底三件套禁止回退**：autoRepark / forceEject / 蠕动保护是自动驾驶防卡死的关键，移除会回归「上车被挤出障碍物」等 bug。
6. **已知边界**：car-pathfinding-test 存在 1 个原版既存失败用例（车到「最近可停处」后 4 车门全被障碍挡 → 留在驾驶态，需玩家 WASD 挪车后 F 下车），非回归（AGENTS.md §12）。
