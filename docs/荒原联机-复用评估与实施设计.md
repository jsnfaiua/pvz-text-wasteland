> 评审人：Senior Developer（高级开发工程师）
> 日期：2026-08-05
> 范围：给《无尽植僵荒原》模组装配联机功能，优先复用本体联机层，并评估嵌入风险、体验影响与模块隔离性。

---

## 0. 结论摘要（TL;DR）

| 问题 | 结论 |
|---|---|
| 本体联机能复用吗？ | **能，且复用面很大**。`Net.mp`（PeerJS 房间层）、`server.js`、账户体系、房间码/邀请链接 UI 流程均为纯传输层，与游戏逻辑解耦，可直接复用。 |
| `mpGame.js` 能直接搬吗？ | **不能直接搬**，但它的**「主机权威 + 快照同步 + 输入上报」模式**应照搬。快照序列化深度绑定本体塔防实体（dave/plants/zombies），需为荒原新建独立同步层。 |
| 嵌入有没有硬伤？ | 无架构级硬伤。三个必须处理的点：①远端玩家对象缺失；②随机性双端不一致（需主机权威）；③客人端不能全量本地模拟（需快照驱动）。均已有成熟解法。 |
| 游玩体验会受影响吗？ | **单机零影响**（隔离设计保证）。联机端按本体内网经验，100ms 快照 + 插值可流畅；公网跨 NAT 延迟升高时客人端会有轻微橡皮筋，可通过增量同步与插值缓解。 |
| 会不会污染其他功能？ | 不会。新建独立模块 `mpWasteland.js` + `sv.mp` 开关，单机路径零改动，`exitWasteland` 时完整清理（含 `Net.mp.close()`）。 |

**最大利好**：荒原世界是 **seed 确定性生成**（`world.js:3-4`：同一 seed + 同一区块坐标永远生成同样内容，存档只存 seed + 差分）。这意味着联机双方**各自本地生成同一世界**，只需同步「seed + 玩家修改差分 + 动态实体」，比本体"固定关卡全量快照"更省带宽。

### 1.3 已知技术债（影响联机落地）

- `survival.js` 117KB「上帝模块」：状态、序列化、逻辑、UI 全在一个文件，联机序列化层需要从这里提取状态白名单。
- 循环依赖较多：`render↔windoor↔wzombie`、`wnpc↔wgear`、`wvehicle→wdev→wnpc→wvehicle`（靠 ES module live binding 运行期解析）。**联机同步层必须避开这些环**，只 import `survival.js` 的导出。
- `mpGame.js` 强依赖未 import 的全局 `Net`（mpGame.js:134），依赖 script 加载顺序——新模块应改为显式 import。

## 3. 联机架构设计

### 3.1 总体数据流（主机权威模型）

```
                    ┌────────────── 房主端（权威模拟）──────────────┐
 房主输入 ──► sv.keys ──► update(dt) 完整模拟 ──► sv（玩家/僵尸/NPC/车辆/世界差分）
                                               │
                ◄──────────── 客人输入 input(50ms) ──┘ 并入 sv.p2 的移动/动作
                ────────────► 快照 sync(100ms)：玩家/僵尸/NPC/车辆/昼夜/背包
                ────────────► 事件 evt（即时）：开箱掉落/击杀/音效/特效
                    └──────────────────────────────────────────────┘

                    ┌────────────── 客人端（快照驱动 + 乐观表现）─────┐
 客人输入 ──► sv.keys ──► ① 上报 host（input）
                         ② 本地乐观移动 sv.px/py（表现层）
                         ③ 接收 sync → 覆写 sv 世界状态 + 远端玩家插值
                         ④ 接收 evt → 即时播放音效/掉落提示
                    └──────────────────────────────────────────────┘
```

### 3.2 消息协议（复用 `Net.mp` 的 `{t, d}` 机制）

| topic | 方向 | 频率 | 内容 |
|---|---|---|---|
| `wstart` | host→guest | 1 次 | 世界 seed、难度、**房主外观**（房主捏完脸后下发；客人随后本地生成世界并**各自捏脸**） |
| `wready` | guest→host | 1 次 | 客人捏脸完成后的外观（host 收到后发 `wgo` 双端同时进入） |
| `wgo` | host→guest | 1 次 | host 确认双方就绪，双端同时 `enterWasteland` |
| `wpos` | 双向 | 200ms | 玩家状态（位置/朝向/动画/HP/外观），双方互发互见（队友可见 + HUD 方向距离指引） |
| `wsync` | host→guest | 100ms | 见 3.4 快照白名单 |
| `wdiff` | host→guest | 事件触发 | 世界区块差分（`sv.mods.tiles` 增量，进入新 chunk 时批量） |
| `wevt` | host→guest | 即时 | 开箱掉落结果、击杀、昼夜切换、音效、特效（对应本体 evt 模式） |
| `wpause` | 双向 | 事件 | 暂停/恢复同步（host 权威裁决） |
| `wdead` / `wend` | host→guest | 事件 | 玩家死亡/结算 |
| `close` | — | — | 断线（复用 `Net.mp` status 'closed'） |

### 3.3 世界同步策略（本方案核心，比本体更省）

- 建房时 host 生成 `seed`，随 `wstart` 下发；**双方各自本地确定性生成世界**（已验证：世界生成路径为纯 hash 驱动，`world.js:58 hash2`；`world.js:66 randInt` 全模组无调用）。
- 玩家对世界的修改（拆墙/建造/搜刮容器/种植）走 `wdiff` 增量同步 `sv.mods.tiles`，只传变更块，**不传全量世界**。
- 客人进入新 chunk 时若缺差分，可向 host 请求补发（增量可靠性兜底）。

### 3.4 实体快照白名单（`wsync` 100ms）

> ⚠️ 禁止 `JSON.stringify(sv)`：`sv` 含 DOM/canvas/函数引用，必须**白名单字段**。这与存档序列化是同一件事，建议落地时先抽 `wstate.js`（见 §8）。

- 双玩家：`p1(host)/p2(guest)` 的 `px/py/hp/maxHp/facing/武器/动作态/饱食/水分/感染`
- 动态实体：`zombies`（id 索引差分，参考 mpGame.js:1115-1150 的 id 合并/移除）、`npcs`、`vehicles`、`bullets`、`effects`（白名单字段）
- 全局：`t/day/昼夜/背包/金钱/任务/尸潮状态/spawnT`
- 房间/室内切换：`interior` 当前所在空间 id（参考 survival.js:608 `sv.zombies = sv.interior.zombies` 的切换点）

**带宽估算**：核心玩家 + 附近几十个实体 ≈ 2-6KB/包，100ms 一包 ≈ 20-60KB/s，远低于 WebRTC data channel 的可用带宽（典型 1MB/s+），无压力。

### 3.5 输入同步与插值渲染（客人端体验核心）

- 客人：`sendInput()` 上报 `sv.keys` 镜像 + 本地玩家状态（照搬 mpGame.js:811-847 结构）。
- 房主：把客人输入并入 `sv.p2` 的移动/动作（与本体 dave2 远端玩家一致）。
- 客人：本地乐观移动自己的 `sv.px/py`（即时响应），收到 `wsync` 后与房主裁决位置做插值纠偏（`_tx/_ty` 插值目标，照搬 mpGame.js:1076-1106 模式）。
- 房主：`wsync` 中带客人玩家的权威位置/HP，客人在本地渲染房主（插值）。

### 3.6 事件通道（即时表现，100ms 快照覆盖不到）

本体已验证的痛点：短命特效等不及 100ms 快照（mpGame.js:766 注释）。荒原同样处理：
- 开箱/搜刮掉落 → `wevt {type:'loot', items}`（主机裁决随机，客人播放开箱动画 + 提示）
- 击杀/伤害 → `wevt {type:'kill'/'hit'}`（音效 + 特效本地复现）
- 昼夜切换、尸潮开始 → `wevt {type:'day'/'horde'}`

## 4. 嵌入检查：问题与风险清单（分级）

| # | 风险 | 等级 | 说明与对策 |
|---|---|---|---|
| R1 | **远端玩家对象缺失** | 🔴 高 | 荒原只有一个主角 `sv.px/py`。需引入 `sv.p2`（远端玩家渲染对象），在 `update()` 移动分支与 `draw()` 处各加一处注入。是唯一必须侵入 `survival.js` 的改动点 |
| R2 | **随机性双端不一致** | 🔴 高 | `wzombie.js:143-290` 大量 `Math.random()`（刷新/掉落/尸潮）。对策：**主机权威**——所有决策只在 host 跑，guest 端在 `sv.mp` 模式下**跳过世界模拟决策**（僵尸 AI/刷新/掉落/昼夜推进），只保留表现层 |
| R3 | **客人端全量本地模拟会分叉** | 🔴 高 | 客人端 `update(dt)` 也会推 `sv.t/昼夜/饥饿/水分`。对策：guest 端 `update` 顶部 `if (sv.mp?.role==='guest')` 分流——世界/实体状态改由快照覆写，本地只推进特效/插值/输入 |
| R4 | **无限地图不能全量快照** | 🟠 中 | 对策见 §3.3（seed + 差分）。本体全量快照方案在此不成立，是本方案与本体最大的差异点 |
| R5 | **循环依赖区** | 🟠 中 | `mpWasteland.js` 只 import `survival.js` 导出，不得 import render/windoor/wzombie 等环内模块，避免把同步层拖入环 |
| R6 | **面板/菜单互斥** | 🟠 中 | 背包/储物柜/NPC 菜单是**本机 DOM 覆盖层**，联机时只操作者可见（合理）；但**开箱掉落由 host 裁决**（R2），客人的搜刮动画由 `wevt` 驱动；暂停需 `wpause` 双端同步（host 权威），否则世界状态会分叉 |
| R7 | **死亡规则未定义** | 🟠 中 | 本体是 gameEnd 双端散场。荒原需定义：单人死亡 → 全队失败/复活机制/旁观模式，建议 v1 采用「任一玩家死亡 → 双端结束并结算」，逻辑最简单 |
| R8 | **断线/退出** | 🟡 低 | 参考本体：status 'closed' → 双端退出荒原回菜单（`exitWasteland` + `Net.mp.close()`）；退出荒原时强制清理联机会话，防止残留 Peer 节点 |
| R9 | **双循环竞争** | 🟡 低 | 本体 `mpGame` 与荒原 `loop` 不应共存（一个游戏循环在跑）。入口互斥：荒原联机只从 workshop 荒原入口进，`enterWasteland` 内先 `Net.mp.close()` |
| R10 | **全屏/输入冲突** | 🟡 低 | 荒原启动会请求全屏（survival.js:2359），联机时两端的按键监听都在 window 上，客人的键已被 `initInput` 记录——需要确认客人端按键不触发本机不存在的操作（在 `sv.mp` 分流中一并处理） |

## 5. 游玩体验影响评估

| 维度 | 评估 |
|---|---|
| 单机体验 | **零影响**。`sv.mp` 默认为 null，所有分支不激活，`mpWasteland.js` 仅在联机会话中加载 |
| 联机流畅度 | 内网（本机 + 局域网）按本体经验流畅：100ms 快照 + 位置插值，手感由「本地乐观移动」保证，无明显输入延迟 |
| 公网/跨 NAT | PeerJS 公共云信令 + WebRTC P2P，打洞成功则延迟可控；失败则延迟升高，客人端表现为轻微橡皮筋。缓解：快照 100ms 内插值 + 增加位置预测 |
| 画面同步 | 远端玩家/僵尸/NPC 插值渲染，与本体 dave2 表现一致；短命特效走 `wevt` 即时复现，观感接近单机 |
| 资源占用 | 新增 1 个同步模块 + 定时器（与本体 mpGame 相同量级），对 60fps RAF 主循环无影响 |

## 6. 隔离性设计（独立模块，不影响其他功能）

1. **零侵入本体联机**：不改 `net.js` / `mpGame.js` / `multiplayerUI.js` 本体文件，只复用其导出接口与 DOM。
2. **荒原内部零侵入单机**：`sv.mp` 开关 + `sv.p2` 远端对象，单机路径（`sv.mp == null`）完全走原逻辑。
3. **生命周期闭环**：`enterWasteland` 入口处 `Net.mp.close()` 兜底；`exitWasteland` 增加联机清理（关定时器、`Net.mp.close()`、移除 `wevt/wsync` 监听），保证退出后无残留监听/定时器/Peer 节点。
4. **命名空间**：新消息 topic 全部 `w` 前缀（`wstart/wsync/wdiff/wevt/…`），与本体 `sync/input/evt` 隔离，双端互不干扰。
5. **DOM 隔离**：联机状态提示复用 `#mp-status`，或新建 `#wmp-status`，不触碰 `#game` 画布与 `panel.js` 覆盖层逻辑。

## 8. 团队代码质量提升建议（随联机落地一并进行）

联机装配会放大存量架构问题，建议同步推进以下改进（优先级从高到低）：

1. **拆分 `survival.js` 上帝模块（117KB）**：至少抽出 `wstate.js`（sv 结构 + 序列化/反序列化）与 `winput.js`（输入采集）。联机序列化、存档、输入三处都依赖，抽出来是联机落地的前提，也是长期可维护性的关键。
2. **消灭循环依赖**：`render↔windoor↔wzombie`、`wnpc↔wgear`、`wvehicle→wdev→wnpc→wvehicle`。建议按依赖方向拆：叶子模块（纯数据/工具）先行，环内函数通过参数注入或事件解耦。
3. **网络层协议文档化**：`{t, d}` 机制很好，但 topic 清单散落各处。建议在 `docs/` 维护一张「联机消息协议表」，本体与荒原分开列，注明方向/频率/字段。
4. **显式依赖**：`mpGame.js:134` 直接使用未 import 的全局 `Net`。新代码一律显式 import，禁止依赖 script 加载顺序。
5. **序列化规范**：禁止 `JSON.stringify` 整个状态对象；所有快照必须白名单字段。把这条写进 AGENTS.md 的编码规范。
6. **可测试性**：联机同步层必须是纯函数可测（`serializeSV / applySnapshot / mergeDiff`），纳入 `dev-tools/smoke-test.js`；同时为 `wstate.js` 增加存档往返测试。
7. **提交规范**：每个 Phase 一个独立提交（如 `feat(wasteland-mp): add host-authoritative sync core`），避免大杂烩提交。

## 附 2：泰拉瑞亚式「角色 / 世界」分离存档（2026-08-05 落地）

联机快照字段与单机存档是同一件事（§3.4 白名单）。为支持"角色物品/属性跨世界保留"，存档从单一混合档拆为**角色档 + 世界档**：

| 存储键 | 内容 | 生命周期 |
|---|---|---|
| `wasteland_profile` | `{characterName, worldSeed, 开发者标记}` | 当前组合，进游戏自动恢复 |
| `wasteland_characters` | `{names: []}` | 已创建角色索引 |
| `wasteland_character_<名>` | 名字/外观/背包/快捷栏/HP/饱食/水分/感染/体力/弹匣 | **跨世界保留** |
| `wasteland_world_<seed>` | seed/时间/天数/NPC/僵尸/世界差分(tiles)/位置 | **跟种子走** |
| `wasteland_save`（旧） | v3 混合档 | 迁移源，迁移后 `_migrated` 标记 |

- `wstate.js` 新增 `serializeCharacter/applyCharacter/serializeWorld/applyWorld` 纯函数（白名单，可单测）。
- 旧档自动迁移：首次进游戏把 `wasteland_save` → 默认角色「幸存者」+ 世界档 + profile。
- 种子查看/修改：workshop 荒原页角色下拉 + 种子输入框（创建前可看可改）；P 键暂停面板显示「世界种子 N · 角色 名」。
- **联机不落档**：`enterWasteland` 带 `opts.mp` 时走原联机路径（角色/世界档不动），单机走角色系统——两条路径隔离。
