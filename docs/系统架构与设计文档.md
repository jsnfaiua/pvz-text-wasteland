## 1. 总览

浏览器端"文字主题"塔防 + 生存游戏。入口 `index.html` → `game-init.js`（本体塔防）；
荒原模组为独立生存沙盒（`survival.js` 主控 + RAF 主循环），与本体共存于同一页面，
通过 `showScreen('game')` 切换；联机复用 `net.js` 的 PeerJS 房间层（`window.Net.mp`）。

```
┌──────────────────────────────────────────────────────────────┐
│ 入口层  index.html · game-init.js · net.js · server.js(:8000, :9000) │
├──────────────┬──────────────────────┬─────────────────────────┤
│ 本体          │ 荒原模组 mod-wasteland │ 联机 multiplayer/       │
│ core/        │ survival.js(主控)     │  mpGame.js · mpWasteland│
│ systems/     │ render.js · world.js  │  wstate.js(序列化真相源) │
│ entities/    │ wzombie/wnpc/wvehicle │  wevt/wsync/wdiff 协议   │
│ ui/          │ wbuild/wplants/wgear  │                         │
│ persistence/ │ wdev/wdistrict/...    │                         │
└──────────────┴──────────────────────┴─────────────────────────┘
```

设计原则（AGENTS.md）：ES Modules、4 空格、分号、单引号、camelCase/UPPER_SNAKE、
模块聚焦、纯函数优先、依赖方向明确。**荒原模组内部存在既定循环依赖区**（见 §3.2），
新增模块不得拖入环内。

## 3. 关键架构事实（勿破坏）

### 3.1 序列化唯一真相 = `wstate.js`
- **禁止 `JSON.stringify(sv)`**：sv 含 DOM/canvas/函数引用，必须白名单字段。
- `serializeSV / serializeWorld / serializeCharacter / serializeMpSnapshot / applySnapshot /
  applyWorld / applyCharacter / applyMpSnapshot / createRunDefaults` 全部纯函数、无环，
  环内模块依赖（B/panel/WNPC/normalizeLook/PLAYER_INFECTION/saveData）由 `survival.js`
  组装成 `STATE_DEPS` 注入（`wstate.js` 本体可 Node 单测）。
- 存档/联机共用同一套白名单 → 双端字段天然一致，杜绝"存档有、快照没"的漂移。

### 3.2 循环依赖区（新增模块勿拖入）
- `render ↔ windoor ↔ wzombie`、`wnpc ↔ wgear`、`wvehicle → wdev → wnpc → wvehicle`。
- 新模块如需使用环内函数：通过函数参数/回调注入，或在 `survival.js` 组装时传入。

### 3.3 泰拉瑞亚式双档
- 角色档 `wasteland_character_<名>`（名字/外观/物品/属性，跨世界保留）。
- 世界档 `wasteland_world_<seed>`（seed/时间/差分 mods/NPC，跟种子走）+ profile
  （当前角色+世界组合、开发者标志）。
- `buildRun` 加载时自动迁移历史档（路带内 built SIDEWALK → 还原路面）。

### 3.4 世界确定性
- 世界完全由 seed 确定性生成（`world.js` 纯函数 hash2）；存档只存 seed + 差分
  （`sv.mods.tiles` 等），读档按 seed 重建基底再叠加差分。
- `T.FLOOR` 与 `T.SIDEWALK` 同值 `'·'` —— **诊断必须对象值比较，勿用字面量判等**。

## 4. 数据流

### 4.1 单机主循环（survival.js `loop`）
```
RAF loop
 ├─ dt 钳制(≤0.05s)
 ├─ update(dt)：sv.now/t 推进 → 特效/掉落上限清理 → 饱食/水分/回血
 │     → 室内? updateInteriorMode
 │     → 驾驶? WV.updateChauffeurDrive / updateDrive（帧内分帧 BFS）
 │     → WA.updateActions(移动/闪避) → WZ.updateSpawns/updateZombies
 │          （共享反向 A* 流场 getPlayerPathField，0.35s 冷却节流）
 │     → WP.updatePlants → WG.updateBullets → 掉落拾取 → purgeChunks
 │     → saveT 到期 → saveNow()（宏任务队列落盘）
 │     → 联机 host：hostGuestBiteCheck（0.1s 一跳，8 格粗筛）
 ├─ draw()：静态层离屏缓存命中 / 重建 → 动态层逐帧 → 实体 → HUD
 └─ requestAnimationFrame(loop)
```

### 4.2 联机数据流（2+ 人，host 权威）
```
host 权威模拟世界          guest 只模拟自身
wpos  200ms 双向           {x,y,face,anim,hp,driving,inInterior,食物水分}
wsync host→guest 100ms     世界快照（白名单+空间裁剪 34 格）
wevt  双向 50ms outbox      击杀/攻击/拾取/箱子/建造/特效/音效/dev 等事件
wdiff 双向（wevt 内）       世界修改增量（setTile → mods.tiles）
winit host→guest 进入时     世界基线（mods 全量）
wrejoin guest→host 重连时   状态重同步请求
```

- **host 权威**：世界模拟（昼夜/僵尸/NPC/刷怪/尸潮/掉落生成）只有 host 跑；
  guest 端 `updateGuest` 分流：只推进自身移动/生存/武器视觉/特效/事件播放。
- **guest 禁止本地扣血**：被咬由 host `hostGuestBiteCheck` 判定，权威 hp 经 wsync
  `guestHp/guestsHp` 下发；guest 只处理"下降"与死亡，回血保留本地值。
- **战斗 host 权威**：guest 攻击经 `atk` 上报 → host 判定命中/击杀 → `kill` 广播；
  guest 本地只画挥砍/枪口特效与音效。
- **僵尸运行时 id**（`sv._zIdSeq` 'zNNN'）：快照按 id 合并（保留插值 _tx/_ty 平滑），
  击杀按 id 指定；旧档/室内补确定性 id（'w'+seed+'_'+i），前缀不冲突。
- **NPC 队伍各自本地管理**：wsync 不带 npcs（防 host controllerId 覆盖 guest 主控）；
  host 权威 NPC 位置经 `npcPos`（轻量）下发渲染，guest 本地 AI 对 `_mpRemote` 停摆。
- **dev 属性共用**：wsync 白名单 `dev` 块 + `devflags` 事件回传，双方图标/效果一致；
  召唤类（僵尸/尸潮/NPC）host 权威执行（`devcmd` 回传）。
- **断线重连**：guest 重连 → `wrejoin` → host 重发 winit + 立即补 wsync；重连期间
  guest 本地世界继续运行。

## 5. 单机 / 联机体验零差异（硬性目标）

**原则：联机模式除了"允许增加一个或多个玩家一起游玩"之外，所有玩法规则、操作反馈、
数值表现、特效、音效、UI、掉落、结算、进度/存档表现都必须与单机完全一致；
任何不一致不得作为"设计性差异"保留，必须修复。**

### 5.1 一致性清单（开发/审查 Checklist）

| 维度 | 检查点 | 现状 |
|---|---|---|
| 玩法规则 | 建造/拆解/种植/合成/交易/雇佣/驾驶规则与单机一致 | ✅ |
| 操作反馈 | 拾取、收集、攻击命中、受伤、开箱、上下车的手感与反馈一致 | ✅ |
| 数值表现 | 伤害/血量/掉落/消耗/成长数值由同一 `wbalance` 常量与 host 权威结算 | ✅ |
| 特效 | 击杀/命中/枪口/防反/爆炸/死亡特效双端可见（wsync effects + wevt fx） | ✅ |
| 音效 | 本端本地播放 + outbox `sfx` 事件让对端也播（伐木/开采/枪声/受击等） | ✅ |
| UI | HUD/血条/背包/商店/捏脸/暂停/开发者面板双端一致；暂停双向广播 | ✅ |
| 掉落 | host 权威生成 → wsync 下发；guest 拾取上报 `pickup` 防重复刷 | ✅ |
| 结算 | 尸潮击退/任务奖励 host 结算并广播 `announce` | ✅ |
| 进度/存档 | 世界档归 host（含双方 wdiff），guest 只落角色档；重连后世界一致 | ✅ |

### 5.2 联机开发注意事项（硬规则，违反 = 不一致 bug）

1. **序列化返回结构必须与消费方断言一致**：对象 vs `Array.isArray` 断言不符会**静默失效**
   （联机教训 #1）。新增快照字段时双端同时改，并补 smoke 断言。
2. **host 权威字段，guest 端发起的变更必须上报回传**：否则"改了被还原"（教训 #2）——
   wdiff/setTile、箱子存取、拾取、丢出、NPC 交易、雇佣均走 wevt 上报 → host 应用 → 回传。
3. **双向全局事件（camp/pause）放 onWevt 开头统一处理**（教训 #3），直接本地应用不广播防回环。
4. **NPC 队伍不随 wsync 同步**：各端管理自己队伍；guest 操控 NPC 用 `npcctl` 事件，
   host 让渡该 NPC 的 AI。
5. **guest 端禁止直接扣自己 hp**：一切受伤由 host 判定；本地回血可保留，但死亡必须同步。
6. **特效/掉落/植物同步做空间裁剪**（34 格半径）：视野外实体无可见差异，走进后 100ms 内出现。
7. **音效必须双端可听**：本地播完要 outbox `sfx` 通知对端（带 snd 名与参数）。
8. **暂停必须同步**：任何一端暂停 → 对端同步暂停（`pause` 事件）；防"一端暂停另一端被打"。
9. **僵尸 id 是联机合并的锚**：新增僵尸必须走 `spawnZombie`（分配 id）；不要手工 push 无 id 对象。
10. **改 wstate.js 后必跑 smoke-test + full-run-test**；改存档键结构后双端存档兼容测试。

### 5.3 新功能默认要求（2026-08-07 增补，硬性）

**所有新开发的功能必须从一开始满足联机 / 单机零差异，禁止「单机先行、联机后补」。**
- 新状态 / 实体 / 掉落 / 结算字段必须进 wstate.js 白名单（存档与 wsync 共用），并补 smoke 断言；
- 伤害 / 掉落 / 结算 / 召唤 / 交易 / 建造必须 host 权威，guest 只上报意图 + 画表现；
- 新音效 / 特效 / UI 反馈必须双端可见（wsync / wevt / outbox sfx）；
- 完成后按 AGENTS.md §5.1 检查表 + §9 验证矩阵双端实测，确认零差异才算完成；
  违反 = 缺陷，「功能单机正常但联机不一致」不得作为已知问题发布。

## 6. 性能架构（帧率防线）

### 6.1 已落实的帧率防线（2026-08-06 排查修复）

| # | 问题 | 根因 | 修复 |
|---|---|---|---|
| P0-1 | 周期性卡顿（20s 一跳帧尖峰） | `saveNow` 在 RAF 帧内同步 `JSON.stringify` 整包世界档 + localStorage 写入（几百 KB） | 改为宏任务队列（`_saveQueued` 合并 + setTimeout 0），退出/切后台 `flushSave` 同步兜底 |
| P0-2 | 开车/疾跑时卡顿 | 僵尸共享反向 A* 流场以"玩家所在格"为 key，高速移动每换格全量重建（上限 1.2 万节点）≈ 7 次/秒 | `_pathRebuildCd` 0.35s 冷却复用旧场（仅换格触发；地形 revision/强制标记不受限） |
| P0-3 | 同屏协同卡顿 | wsync 100ms 全量序列化 ALL plants（`Object.entries(sv.mods.plants)`）+ 全部掉落（≤150）+ 特效（≤50），无空间裁剪 → 双端 JSON+GC 压力 | `getMpSnapshot` 按 host+guests 视野 34 格裁剪 drops/effects/bullets/plants；`serializeMpSnapshot` 支持 cull 参数 |
| P0-4 | 坐车（NPC 驾驶）卡顿 | ① `chauffeurBuildPath` 同步展开最多 6 万格（30-60ms 单帧尖峰）；② **NPC 订单到达时 `stopDrive(sv,null)` 乘客下车环调用空 `canStand` → TypeError → RAF 主循环死亡 → 游戏冻结** | ① BFS 分帧化：每帧格数预算（首建 6000/重建 3000，确定性、与 CPU 无关）；② 乘客落点验证 null 安全（退化 isWalk 判定） |
| P1-5 | 特效合并 O(n²) | guest `applyMpSnapshot` 每快照特效线性 find（50² 比较/100ms） | 键控 Map（kind+12px 桶）O(1) 合并 |
| P0-8 | 联机 host 周期性帧尖峰（host 卡 → guest 体感跟着卡） | `buildPlayerPathField` targets=全部僵尸（含远处 18-26 格）→ 远处僵尸不在流场 reachable → `updateZombies` 每 0.5s 标记重建 → 全量 A*（1.2 万节点）周期重建 | targets 近距化（仅警戒范围 Z_CHASE_RANGE=8 方形内 + 尸潮僵尸）+ 重建标记加 `playerAlerted` 门控；行为等价（警戒外僵尸原本就游荡不追），流场展开范围从全地图缩至 4 格半宽 |
| P2-6 | NPC 畸形数据冻结 | `eatFromInv/drinkFromInv/workLog` 对缺字段 NPC（旧档/联机快照/开发者召唤）无防御 → 主循环崩溃 | `Array.isArray(n.inv)`/`workLog` 守卫，缺字段跳过 |

### 6.2 帧率影响因素清单（排查顺序，全部已核对）

1. **主循环更新耗时**：`loop` 内 update 各子系统按 §4.1 顺序执行，成本大头是 A* 流场（已节流）
   与 NPC/僵尸遍历（僵尸场上限 HORDE_MAX_ONFIELD=45 + 野怪/尸群，NPC 远离降频 0.3s 一跳）。
2. **实体数量增长/泄漏**：特效 ≤50、掉落 ≤150、子弹 ≤80 均有硬上限；NPC 死尸帧边界移除；
   chunk 缓存 `purgeChunks` 每 5s 清理。
3. **NPC AI / 寻路 / 车辆驾驶**：僵尸共用流场（一次 A* 服务全队）；车辆 BFS 分帧 + 路径缓存
   （首次/换目标/被挡 2s/空路径 1.5s 才重建）；`carCanStand` 逐帧走帧级车体缓存。
4. **渲染绘制**：静态层离屏 canvas 缓存（rev/seed/视口 三维 key），地块变化才重建；
   动态层逐帧只画视野内实体；像素画以 fillRect 为主。
5. **Canvas 文本/阴影/滤镜**：文本仅僵尸名字/血条/特效标签；`shadowBlur` 仅 muzzle 特效（≤50 个）；
   饥饿光晕 `createRadialGradient` 仅在危急状态绘制。
6. **镜头与 UI 面板**：相机跟随为纯坐标计算；`fitCanvasBacking` 只在尺寸变化时重测（resize/DPR 监听失效）；
   HUD 每帧重绘但为廉价矢量绘制。
7. **网络快照序列化/反序列化**：100ms wsync 全量 → 已裁剪（P0-3）；guest 端僵尸按 id 合并 + 位置插值。
8. **消息广播/转发频率**：wpos 200ms、wsync 100ms、outbox 50ms 三个定时器；atk 上报 60ms 节流；
   msg 播报 150ms 节流。定时器均先 stop 再 start，无重复注册。
9. **音频开销**：WebAudio 一次性触发音（短振荡/缓冲），无长驻节点堆积。
10. **存档写入阻塞**：已移出帧循环（P0-1）。
11. **DOM 更新**：联机 toast/在线人数低频更新；面板打开/关闭才操作 DOM。

## 8. 近期功能变更记录（2026-08-07 起）

> 按 §11.3 记录行为变更的用法与配置。代码归属见 git 提交；数值收口见 `wbalance.js`。

### 8.1 死亡系统（两难度分流）
| 难度 | 死亡行为 | 用法 |
|---|---|---|
| 正常（`normal`，soft） | 被队友救回：**不掉装备但掉全部背包物品** → 原地生成「遗物包裹」（`loot:legacy`，金色），屏幕外有金色方箱指引「遗物包裹 · N格」；部分物品因「不可抗力」永久消失，比例 `deathVanishRate(死亡次数)`（首次 30%、每次 +10%、封顶 60%，`DEATH_VANISH_BASE/STEP/MAX`），消失判定走 `hash2(seed, 死亡格, 槽位+次数)` 确定性纯函数（§13.2：包裹内容进存档不得用 Math.random） | 醒来后循指引拾取包裹；`sv._deathCount` 随角色档持久化 |
| 硬核（`hardcore`，一条命） | 死亡即永久：原角色尸化为精英僵尸（名字/外观/装备/背包继承，会用背包远程武器射击）；死亡界面双按钮「保存世界·重新捏脸归来 / 不保存·彻底离开」 | 保存 → 世界档保留 → 重新命名+捏脸 → 新角色导入同一世界（`enterWasteland({seed: 旧world})`），可见「尸化的自己」（紫色菱形指引） |
- 联机：**任一玩家死亡 → 双端结算退出**（R7 保持，host 权威判定；guest 背包在本地无法由 host 生成包裹/尸化，死亡一律结束，避免 guest 血量归零卡死）。

### 8.2 存档管理 UI（创意工坊 → 无尽植僵荒原详情页）

### 8.6 天气系统（sv._weather，独立于 _evt）
- 5 类（wbalance.js `WX_TABLE`）：晴朗 0.38 / 细雨 0.20 / 飘雪 0.12 / 大雾 0.16 / 沙尘暴 0.14（权重和=1，smoke 断言）。
- 每天 8:00 用 `weatherAt(seed, day)` **确定性切换**（§13.2：世界状态禁 Math.random）；单机/联机 host 同一公式，guest 经 wsync 快照 `weather` 字段同步（§5.1 零差异）。
- 沙尘暴并入天气（保留 0.7 减速，废止旧 `_evt.type='sandstorm'` 判定）；blackout/airdrop 保留 `_evt`（host 权威，wsync `evt` 字段同步）。
- 玩法联动：`wxInfo(sv._weather).speedMul` 全局减速（雪雾 0.9、沙尘暴 0.7）。
- 渲染（动态）：
  - `drawWeatherOverlay` — 沙色呼吸暗角 / 大雾弥漫 / 雨雪冷调（呼吸脉动 `Math.sin(sv.now*1.6)`）
  - `drawWeatherParticles` — 雨丝斜线下落 / 雪花摇摆飘落 / 飞沙横飞（屏幕空间固定粒子池 140，密度随 `_devGfx`：低 0 / 中 60% / 高 100%；现实秒驱动暂停静止）
